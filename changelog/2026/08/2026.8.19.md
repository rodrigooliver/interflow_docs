## Novas Funcionalidades

### Campo `contact` na API de criar chat

O `POST /chat/create` lê o destinatário em `customer`, conforme o canal: WhatsApp usa `customer.whatsapp` (ou `phone`), e-mail usa `customer.email`, Instagram/Facebook usam o ID correspondente. Nome, documento, tags e custom fields também vão nesse objeto.

#### Para que serve?

- Simplificar Make, n8n e outras automações: só o número (ou ID) e o `channelId`
- Evitar inconsistência entre o tipo informado e o canal escolhido
- Encontrar o mesmo cliente se o CRM gravou `instagram` e o inbound gravou `instagramId`

#### Como usar?

1. Envie `channelId` + `customer.whatsapp` (ou `email` / `instagram` / `facebook`)
2. WhatsApp Oficial, WAPI, Z-API, WAHA e EVO usam `customer.whatsapp` (ou `phone`)
3. No mesmo objeto, envie nome, documento, tags e custom fields
4. Use `customer.forceUpdate` (`{ "name": true, "document": true, "customFields": ["investimento"] }`) para sobrescrever campos já preenchidos
5. Documentação: [Criar Chat](/api/chats/create)

## Benefícios

- Payload menor e alinhado ao canal
- Integrações novas não precisam adivinhar o enum de tipo
- Clientes criados pelo inbound (Instagram/Facebook) são reaproveitados na abertura via API
