## New Features

### Templates when creating task projects

When creating a project in **Tasks**, you can pick a **template** with ready-made columns — and, when it makes sense, with automation rules already configured.

#### Available templates

| Template | Columns | Initial automations |
|----------|---------|---------------------|
| **Free** | Backlog | None (you build from scratch) |
| **By status** | To start · In development · Done | Syncs status ↔ column |
| **By priority** | Low · Medium · High | Syncs priority ↔ column |
| **Simple sprint** | Backlog · In progress · In review · Done | Syncs “Completed” ↔ Done |

#### What is it for?

- Start a Kanban that matches how your team works
- Avoid setting up columns and rules from scratch every time
- Keep status (or priority) and column consistent

#### How to use?

1. In **Tasks**, create a **new project**
2. Choose the desired **template**
3. Confirm — columns (and automations, if any) are ready
4. Adjust names, colors, or rules later if needed

> Full guide: [Task project templates](/en/guide/tasks/templates)

### Task project automations

Each project can have **ordered rules** that watch task creation or updates and apply actions automatically — similar to Kanban board automations.

#### What rules can do

- **When:** task created or updated
- **If:** conditions on status, stage (column), priority, archived state, and due date — including comparing values **before** and **after** the change
- **Then:** change status or column, set priority, archive/unarchive, clear due date, create a follow-up task, or start a silent flow

Status and archive changes made by automation write **history** and send **notifications** to project members (with notifications enabled), just like manual start, complete, or cancel actions.

#### What is it for?

- Move the card automatically when status changes (and the other way around)
- Standardize the flow without relying on someone remembering to drag the card
- Chain follow-ups or flows when a task reaches a state

#### How to use?

1. Open the project in **Tasks**
2. From the project menu, open **Automations**
3. Create or edit rules (event → conditions → actions)
4. Set the order and enable/disable as needed

::: tip Avoid loops
Template rules only fire when the other side is not already at the target — for example, changing status will not move the column if the card is already there.
:::

> Full guide: [Task project automations](/en/guide/tasks/project-automations)

### Project default stage

Every project now has a **default stage**: the column pre-selected when creating a new task in that project (on project creation, it is the template’s first column).

#### What is it for?

- Speed up task creation in the right board column
- Avoid tasks with no column or the wrong stage by mistake

#### How to use?

1. Edit the project in **Tasks**
2. Choose the **default stage**
3. When creating a task in that project, the column is already selected

## Improvements

### Smoother task board

- **Dragging** a card updates the board immediately (optimistic), with a discreet sync indicator on the bottom edge
- While syncing after a drag, the card blocks other actions
- When **starting** or **completing** from the card, the button shows “Starting” / “Completing” while loading
- When automation moves a card (without dragging), there is a subtle enter animation in the new column
- Realtime updates skip the echo of your own action and sync changes from others and from automation

## Benefits

- Ready-to-use projects with templates for status, priority, or sprint
- Less manual work to keep column and status (or priority) in sync
- Automations with the same history and notifications as manual actions
- A more responsive board when dragging, starting, and completing tasks
