## Nuevas Funcionalidades

### Campo `contact` en la API de crear chat

`POST /chat/create` lee el destinatario en `customer` según el canal: WhatsApp usa `customer.whatsapp` (o `phone`), email usa `customer.email`, Instagram/Facebook usan el ID correspondiente. Nombre, documento, tags y custom fields también van en ese objeto.

#### ¿Para qué sirve?

- Simplificar Make, n8n y otras automatizaciones: solo el número (o ID) y el `channelId`
- Evitar inconsistencia entre el tipo informado y el canal elegido
- Encontrar el mismo cliente si el CRM guardó `instagram` y el inbound guardó `instagramId`

#### ¿Cómo usarlo?

1. Envíe `contact` + `channelId` (y los demás campos opcionales de siempre)
2. WhatsApp Oficial, WAPI, Z-API, WAHA y EVO tratan el valor como WhatsApp
3. Instagram y Facebook usan el ID del contacto; email usa la dirección
4. Use `customer` para email, teléfono, WhatsApp y documento
5. Documentación: [Crear Chat](/es/api/chats/create)

## Beneficios

- Payload más corto y alineado al canal
- Las integraciones nuevas no necesitan adivinar el enum de tipo
- Los clientes creados por inbound (Instagram/Facebook) se reutilizan al abrir el chat por API
